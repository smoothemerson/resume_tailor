<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM output → guard functions | Untrusted LLM-generated LaTeX string enters _check_* functions |
| Guard functions → stderr | Warning strings derived from LLM content are written to stderr |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | TailorResult.fences_stripped computation | mitigate | Compute `raw.strip() != _strip_fences(raw)` before any mutation; _strip_fences is idempotent so double-call is safe |
| T-04-02 | Information Disclosure | logger.warning() prints LLM-derived section names to stderr | accept | Section names come from original resume (trusted source), not from LLM output; employer names in GUARD-03 warnings also come from original. Low risk — local CLI tool. |
| T-04-03 | Denial of Service | Catastrophic regex backtracking on adversarial LLM output | mitigate | All three guard regexes are linear (no nested quantifiers); `re.findall(r'\\header\{([^}]+)\}')` uses `[^}]+` which cannot backtrack. Verified against english.tex. |
| T-04-04 | Elevation of Privilege | Guard exception propagating to cli.py try/except, aborting write | mitigate | Each _check_* function wraps body in `try/except Exception`; run_guards never raises; GUARD-04 architectural requirement |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase; stdlib + existing modules only |
</threat_model>

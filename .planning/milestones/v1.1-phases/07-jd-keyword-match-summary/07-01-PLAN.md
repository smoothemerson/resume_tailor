<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM output -> analysis dict | The analysis dict originates from jd_analyzer.py which parses LLM-generated JSON. Keywords are LLM-generated strings. |
| analysis dict -> regex engine | Keyword strings are passed to re.escape() before inclusion in a regex pattern. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering | re.escape(kw.lower()) in _match_keywords | mitigate | re.escape() is applied to all keyword strings before regex compilation — prevents regex injection via LLM-generated keyword content |
| T-07-02 | Denial of Service | Large keyword list from analysis dict | accept | LLM output is bounded by model context window; keyword lists are small (typically <50 items); no loop amplification risk |
| T-07-03 | Information Disclosure | Match summary printed to stdout | accept | Tool is a local CLI for personal use; stdout output is intentional and TTY-gated; no sensitive data disclosed |
| T-07-04 | Spoofing | sys.stdout.isatty() check | accept | TTY check is process-level; no trust boundary crossing; suppression on non-TTY is a UX feature, not a security control |
| T-07-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase; stdlib only; no supply chain risk |
</threat_model>

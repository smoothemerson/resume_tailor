    Create src/jd_analyzer.py. No docstrings, no inline comments per CLAUDE.md conventions.

    Imports: import json, import re, import requests, from config import OLLAMA_BASE_URL, OLLAMA_MODEL, TIMEOUT.

    Private helper _build_analysis_messages(job_description: str) -> list[dict]: returns a 2-element list [system, user]. System prompt instructs the model to extract structured info and return ONLY a valid JSON object with exactly three keys: technologies (list of strings), requirements (list of strings), emphasis_areas (list of strings) — no explanation, no markdown, no prose. User message wraps job_description in <job_description>...</job_description> XML tags matching the existing pattern in llm_client.py lines 97-104.

    Private helper _parse_analysis_response(content: str) -> dict | None: strips markdown fences from content using the same two re.sub patterns as _strip_fences in llm_client.py lines 113-115, calls json.loads on the stripped content, validates that required_keys = {"technologies", "requirements", "emphasis_areas"} is a subset of parsed.keys(), returns {k: parsed[k] for k in required_keys} on success. Returns None if json.loads raises or keys are missing. Does NOT raise on parse failure.

    Public function analyze_job_description(job_description: str, model: str | None = None) -> dict | None:
    - effective_model = model or OLLAMA_MODEL
    - messages = _build_analysis_messages(job_description)
    - payload = {"model": effective_model, "messages": messages, "stream": False}
    - Outer try block wraps the entire POST + response.json() + done_reason check + _parse_analysis_response call
    - Inside try: POST to f"{OLLAMA_BASE_URL}/api/chat" with json=payload, timeout=TIMEOUT; call response.raise_for_status(); data = response.json(); check data.get("done_reason") == "length" and raise RuntimeError("JD analysis response was truncated (done_reason=length).") if true; raw = data["message"]["content"]; return _parse_analysis_response(raw)
    - except RuntimeError: raise — re-raises the done_reason RuntimeError (non-recoverable truncation)
    - except Exception: return None — catches all other failures (ConnectionError, HTTPError, JSONDecodeError, KeyError, etc.) and returns None silently per D-04

    Critical structural point: the done_reason check raises RuntimeError INSIDE the outer try block. The except RuntimeError: raise clause then re-raises it out past the except Exception: return None clause. This is the pattern shown in 06-PATTERNS.md non-fatal fallback section. Without this re-raise, the except Exception clause would swallow the truncation error and return None — which would bypass the D-05 PIPE-04 requirement.

    Do NOT call _check_ollama_health() anywhere in this file — per anti-patterns in RESEARCH.md (health check is already called in generate_tailored_resume; calling it again in the analysis pass causes a double health check per run).

    Do NOT add "options": {"num_ctx": 8192} to the payload — jd_analyzer input is only the job description (shorter than a full resume), no context window pressure. The tailoring call keeps its num_ctx option.

# Requirements Archive: v1.1 Output Quality + Test Coverage

**Archived:** 2026-06-08
**Original defined:** 2026-06-02
**Core Value:** Given a job description, produce a ready-to-compile LaTeX resume that is genuinely better aligned with that job — not just syntactically valid but actually usable.

---

## v1.1 Requirements — All Complete

### Output Guards

- [x] **GUARD-01**: Tool warns when a section present in the original resume is missing from the tailored output — ✓ Validated Phase 4
- [x] **GUARD-02**: Tool warns when tailored output contains markdown prose or other format violations (LaTeX-only rule broken) — ✓ Validated Phase 4
- [x] **GUARD-03**: Tool warns when structured fields (employer names, dates, skills tokens) appear in output but were not in original resume — ✓ Validated Phase 4
- [x] **GUARD-04**: Guards degrade gracefully — any guard failure prints a warning to stderr but does not block the output write — ✓ Validated Phase 4

### Diff View

- [x] **DIFF-01**: Tool shows a normalized unified diff of original vs tailored resume after tailoring, when stdout is a TTY — ✓ Validated Phase 5
- [x] **DIFF-02**: Diff is suppressed automatically when stdout is piped or redirected (no flag required) — ✓ Validated Phase 5
- [x] **DIFF-03**: Diff normalization eliminates whitespace-only noise (trailing space, blank line collapsing) so only meaningful changes appear — ✓ Validated Phase 5

### Two-Pass Pipeline

- [x] **PIPE-01**: Tool performs a JD analysis pass (pass 1) before the tailoring call — extracts key technologies, role requirements, and emphasis areas from the job description — ✓ Validated Phase 6
- [x] **PIPE-02**: Analysis output is injected into the tailoring prompt (pass 2) to guide section-specific rewrites — ✓ Validated Phase 6
- [x] **PIPE-03**: If pass 1 fails (malformed output, parse error), tool falls back to single-pass behavior — no abort, no error surfaced to user — ✓ Validated Phase 6
- [x] **PIPE-04**: Both LLM calls respect existing done_reason truncation guard — ✓ Validated Phase 6

### JD Match Summary

- [x] **MATCH-01**: After tailoring, tool displays which keywords from pass 1's analysis appear in the tailored resume — ✓ Validated Phase 7
- [x] **MATCH-02**: Keyword matching uses whole-word regex with stop word filtering to prevent substring false positives — ✓ Validated Phase 7
- [x] **MATCH-03**: Match summary is displayed to stdout only when running interactively (TTY guard, same as diff) — ✓ Validated Phase 7

### Test Infrastructure

- [x] **TEST-01**: pytest configured in pyproject.toml — testpaths includes both `src` and `tests`, pythonpath set to `["src"]`, three markers registered (`unit`, `integration`, `e2e`), `--strict-markers` and `-ra` in addopts — ✓ Validated Phase 8
- [x] **TEST-02**: `tests/conftest.py` provides a session-scoped `ollama_available` fixture (HTTP probe, runs once per session) and a `require_ollama` fixture that skips the test when Ollama is unreachable — ✓ Validated Phase 8
- [x] **TEST-03**: `tests/` organized into `unit/`, `integration/`, and `e2e/` subdirectories; existing `src/*_test.py` files left in place — ✓ Validated Phase 8

### Unit Test Gaps

- [x] **TEST-04**: `_build_messages()` tested: returns 2-element list with roles `"system"` then `"user"`; user content contains `<job_description>` and `<resume>` XML tags embedding the provided inputs; system content contains `<PERSONA>` and `<CONSTRAINTS>` markers — ✓ Validated Phase 9
- [x] **TEST-05**: `_check_ollama_health()` tested in isolation: raises `RuntimeError` on `ConnectionError`; raises `RuntimeError` on `Timeout`; does not raise when response status is 200 — ✓ Validated Phase 9
- [x] **TEST-06**: `read_resume()` tested: returns file text content when file exists; raises `FileNotFoundError` when file does not exist — ✓ Validated Phase 9
- [x] **TEST-07**: `write_resume()` tested: creates output directory if it does not exist; returns a `Path`; written filename matches `tailored_resume_YYYYMMDD_HHMMSS.tex` pattern; file content equals the input string — ✓ Validated Phase 9

### Integration Tests

- [x] **TEST-08**: Integration test: Ollama health endpoint returns 200 when Ollama is running; test is skipped (not failed) when Ollama is unreachable — ✓ Validated Phase 10 (checkbox in live REQUIREMENTS.md was stale; SUMMARY.md and PROJECT.md confirmed complete)
- [x] **TEST-09**: Integration test: `generate_tailored_resume()` with a minimal synthetic resume and a short JD returns a string starting with `\documentclass` and ending with `\end{document}`, with no markdown fences; test is skipped when Ollama is unreachable — ✓ Validated Phase 10 (same as TEST-08)

### E2E Tests

- [x] **TEST-10**: E2E test: CLI subprocess exits 1 and prints an error to stderr when given empty JD input (END sentinel immediately); does not require Ollama running — ✓ Validated Phase 11
- [x] **TEST-11**: E2E test: CLI subprocess exits 0 when given a real JD, creates an output file in a temp directory with filename matching the timestamp pattern, and stdout contains `"Tailored resume written to:"`; test is skipped when Ollama is unreachable — ✓ Validated Phase 11

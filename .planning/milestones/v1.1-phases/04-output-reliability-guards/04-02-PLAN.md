<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cli.py try block → run_guards | Untrusted LLM output (result.content) enters guard pipeline |
| run_guards → write_resume | Pipeline continues to file write regardless of guard findings |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Tampering | cli.py result.content passed to write_resume | accept | content is the same post-validated LaTeX that was previously written; the only change is the variable name from `content` to `result.content`. No new trust boundary introduced. |
| T-04-06 | Denial of Service | run_guards() exception propagating through cli.py try/except, blocking write_resume | mitigate | Each _check_* function wraps body in try/except Exception (enforced in Plan 01, Task 2); run_guards itself does not raise. The try/except in cli.py is a last-resort safety net, not the primary GUARD-04 mechanism. |
| T-04-07 | Information Disclosure | Warning messages containing LLM-generated section names printed to stderr | accept | Section and employer names in warnings come from the original resume (trusted), not from LLM output. Local CLI tool — no remote disclosure. |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in this phase; stdlib + existing modules only |
</threat_model>

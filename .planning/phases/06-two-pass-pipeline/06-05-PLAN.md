## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-08 | Tampering | analysis dict from LLM output forwarded to second LLM call | accept | dict is created by analyze_job_description which validates keys; no shell execution, no file writes, no SQL — dict content reaches only the tailoring prompt |
| T-06-09 | Denial of Service | two LLM calls double latency per run | accept | Both calls use TIMEOUT; each failure exits cleanly or falls back; no retry loop; user informed via progress messages |
| T-06-10 | Spoofing | LLM analysis result injected into prompt could influence tailoring output | accept | Expected behavior — this is the feature. The LLM (analysis) output guides the LLM (tailoring) input. No privilege boundary exists between the two calls; both run in the same local security context. |
| T-06-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan |

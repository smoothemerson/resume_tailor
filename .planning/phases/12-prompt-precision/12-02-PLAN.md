<objective>
Close the UAT Test 1 gap (12-HUMAN-UAT.md, severity major): the model sometimes inserts technologies from the job description that are absent from the base resume. Root cause (debug session .planning/debug/fabricated-technologies.md): the anti-fabrication guarantee rests solely on the probabilistic TECHNOLOGY FIDELITY prompt rule, undermined by (1) an unannotated `<jd_analysis>` technology list priming the model, (2) no temperature in the Ollama payload so compliance varies run-to-run, and (3) no post-generation fidelity guard.

Scope note: this plan reaches beyond the original 12-CONTEXT.md boundary; the user-confirmed UAT Test 1 gap supersedes that boundary and authorizes the additional surface (guards.py, cli.py wiring).

This plan layers three defenses, one per root-cause factor:
1. Set `options.temperature` to 0.2 in the tailoring payload (variance reduction)
2. Add a labeled JD ANALYSIS USAGE rule to the system prompt and repeat the fidelity constraint inline at the four ALLOWED rewrite sites where fabrication occurs (priming defusal)
3. Add a deterministic `_check_fabricated_technologies` guard to `src/guards.py`, wired from `src/cli.py` (runtime detection)

`src/jd_analyzer.py` is intentionally NOT modified: its output is correct (an accurate JD technology list); the defect is how that list is framed to the model and the absence of downstream enforcement. Guards warn (consistent with the existing warn-only guard pipeline pattern); no retry loop is introduced.

Purpose: make the UAT truth hold — "No fabricated technologies appear in the tailored output" — and, when the model still violates it, surface a named warning instead of passing silently.
Output: updated src/llm_client.py, src/guards.py, src/cli.py, plus new tests in tests/unit/test_llm_client.py and src/guards_test.py. All pre-existing tests pass unmodified except the single run_guards signature assertion at src/cli_test.py:30-34, which is updated to expect the new jd_technologies=None kwarg.
</objective>
